=== Contexte du projet
StreetComplete est une application Android qui permet d’améliorer facilement les données d’OpenStreetMap (OSM). OSM est une carte mondiale collaborative où chacun peut ajouter ou corriger des informations (routes, bâtiments, commerces, équipements publics, etc.).

StreetComplete simplifie cette contribution en proposant des “quêtes” géolocalisées : de petites questions permettant de compléter ou vérifier des données manquantes sur le terrain. L’application mise sur une approche ludique et accessible pour encourager la participation, même sans connaissance préalable d’OSM.

== Fonctionnement du projet 

=== Langage et plateforme
- Plateforme principale : Android (API minimale : 26, API cible : 34), iOS (en cours)
- Langage de programmation : Kotlin (version 2.2.20)
- Build system : Gradle Kotlin DSL
- UI : Android Views + migration progressive vers Compose Multiplatform

=== Cartographie
StreetComplete utilise MapLibre, une collection de cartes SDKs open-source pour du développement web et mobile.

=== Communication entre les serveurs OSM (OpenStreetMap)
- Téléchargement des données OSM via API officielle OpenStreetMap
- Upload des requêtes utilisateurs (ajout, modification et suppression des données OSM à l'aide de tags) dans la base OSM

**Détails des composants principaux :**

**1. Interface utilisateur (Frontend mobile)**

- Application Android en Kotlin.
- Affichage basé sur Mapbox/MapLibre pour la carte.
- Présentation des « quêtes » sous forme de tuiles interactives.
- Gestion des formulaires pour répondre aux quêtes.

**2. Moteur de quêtes**

- Sélection des quêtes pertinentes en fonction de la localisation, des données OSM existantes et des règles.
- Déclenchement des formulaires adaptés (ex : type de surface de route, horaires d’un commerce).

**3. Gestion des données locales**

- Téléchargement et stockage temporaire des données OSM (extraits vectoriels).
- Cache en base de données locale (SQLite).
- Gestion des quêtes en attente (offline-first).

**4. Communication avec OpenStreetMap**

- Authentification via OAuth.
- Téléversement des réponses sous forme de changesets OSM.
- Synchronisation différée si offline.

**5. Services externes**

- Map tiles : MapLibre / Mapbox / serveurs tiers.
- Téléchargement des extraits de données OSM (via Overpass API ou serveur interne).
- API OSM standard (modifications, user account).

**Description :** 

- MainActivity.kt : point d'entrée de l'application.
- StreetMapActivity.kt : gestion de la carte (MapLibre).
- quest/ : gestion des quêtes (affichage, logique, modèles).
- overlay/ : gestion des couches interactives.
- data/ : accès aux données locales et distantes.
- network/ : communication avec l’API OSM.
- res/ : ressources graphiques et layouts.
- utils/ : fonctions utilitaires.

== Annexes
- **Quest (quête) :** Une quêtes est une question ciblée sur des objets OSM manquants ou incomplets dans votre zone (route, bâtiment, équipement). Exemple d'une quête : "Le trottoir existe-t-il ?"
- **Overlay :** Une couche d’affichage interactive permettant de visualiser/éditer directement certains tags OSM
